# Ипотека vs вклад

Локальный веб-калькулятор, отвечающий на один вопрос: **выгоднее положить накопления на вклад
или внести их досрочным погашением ипотеки?**

Заполняется одна форма — текущая ипотека, стратегия досрочного погашения и условия вклада, —
после чего приложение показывает сравнение стратегий с явным победителем: «положить на вклад и
погасить потом», «погасить сейчас и уменьшить платёж», «погасить сейчас и уменьшить срок» и,
если задан месячный бюджет, «снежный ком». Рядом — графики и помесячный график платежей
по каждому сценарию.

## Как запустить

### Вариант 1 — локально, без Docker (для разработки)

```bash
cd /path/to/mortgage-vs-deposit

# один раз: виртуальное окружение и зависимости
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# запуск (обязательно из каталога web/)
cd web
DB_PATH=../db/mortgage_web.db PYTHONPATH=.. flask --app app/main.py run
```

Открыть http://localhost:5000

Флаг для разработки: `FLASK_DEBUG=1` — автоперезагрузка при правке файлов.

**Почему из `web/`:** Python должен найти каталог `web/app/` как пакет `app`.
Из корня репозитория импорты не разрешатся.

`PYTHONPATH=..` сейчас уже не обязателен — `web/app/` больше не импортирует
`tgapp_legacy/`. Оставлен в команде, чтобы она совпадала с тем, что делает Docker-образ.

**Экспериментируя, не поднимайте приложение на `db/mortgage_web.db`:** в ней лежит живая
история сравнений, а старт приложения пишет в базу. Скопируйте её и укажите копию:

```bash
cp db/mortgage_web.db /tmp/mortgage_copy.db
cd web && DB_PATH=/tmp/mortgage_copy.db flask --app app/main.py run --port 5001
```

### Вариант 2 — Docker

```bash
cd /path/to/mortgage-vs-deposit
docker compose up --build
```

Открыть http://localhost:5000

База берётся из репозитория: том смонтирован как `./db:/app/db`, история сравнений
сохраняется между перезапусками контейнера. Это же означает, что контейнер пишет в живую
`db/mortgage_web.db`: для экспериментов лучше собрать образ отдельно и подсунуть копию —
`docker build -t mvd . && docker run --rm -p 5000:5000 -v /tmp:/app/db -e DB_PATH=/app/db/copy.db mvd`.

### Что НЕ надо запускать

`run.sh` — легаси-скрипт телеграм-бота. В нём зашит путь с чужой машины
(`/Users/mariaosipova/...`), поэтому Docker падает с `permission denied`, а собирает он
корневой `Dockerfile`, то есть веб-приложение под именем `morst-bot`. К веб-калькулятору
отношения не имеет.

## Где лежат данные

| Файл | Что это |
|---|---|
| `db/mortgage_web.db` | база веб-приложения: ипотеки, стратегии погашения, вклады, история сравнений |
| `db/morst_bot.db`, `db/morst_bot_old.db` | базы легаси телеграм-бота, приложением не используются |

Таблицы: `mortgage`, `repayment_strategy` (суммы и даты досрочек, режим, правило распределения),
`deposit` (ставка, срок, капитализация — суммы в ней нет, на вклад кладётся тот же `lump_sum`)
и `comparison` (итоги). Графики платежей в базе не хранятся никогда — они пересчитываются.

Схема создаётся и мигрируется автоматически при старте (`web/app/database.py`).
Новые колонки добавляются через `ALTER TABLE` и историю не сносят.

Переменные окружения:

- `DB_PATH` — путь к базе (по умолчанию `../db/mortgage_web.db` относительно `web/`)
- `FLASK_DEBUG` — `1` включает автоперезагрузку

## Тесты

pytest в проекте нет и не планируется — только stdlib `unittest`. Набор растёт; на момент
написания — **137 тестов**, прогон занимает около 25 секунд, ожидаемый итог — `OK`.

```bash
cd /path/to/mortgage-vs-deposit
PYTHONPATH=web .venv/bin/python -m unittest discover -s tests
```

В выводе видны пропуски (`s`) — это подтесты внутри параметризованных кейсов: например,
досрочка «ровно в дату платежа» пропускается там, где в сдвинутой на рабочий день сетке
такой строки нет. На результат прогона они не влияют, ожидаемый итог — `OK`.

### Как понять, что вы что-то сломали

Расчёт закреплён **golden-снимком**: полные графики платежей построчно по матрице входов
(остаток × ставка × досрочка × дата досрочки × режим × рабочие дни × бюджет × день доплаты).
Всего 92 + 2964 + 2205 кейсов на три расчётные функции.

```bash
# сравнить текущий расчёт с закоммиченным снимком, ничего не переписывая
PYTHONPATH=web:tests .venv/bin/python scripts/snapshot_golden.py --check

# что вообще снято и какого размера файлы
PYTHONPATH=web:tests .venv/bin/python scripts/snapshot_golden.py --list
```

`--check` ничего не пишет: он печатает по строке на функцию и либо «0 расхождений», либо
первые расхождения с именем функции, входом и парой «ожидалось / получено», и возвращает
код 1. Это и есть ответ на вопрос «что я сломал»: править код надо до тех пор, пока
`--check` не станет зелёным, а не переснимать снимок под новые числа.

Если числа изменились **осознанно** — снимок переснимается ровно по одной функции и
только с объяснением, которое уходит строкой в `CHANGELOG.md`:

```bash
PYTHONPATH=web:tests .venv/bin/python scripts/snapshot_golden.py \
    --accept simulate_lump_repayment --reason "почему числа изменились"
```

Массовой перезаписи всех снимков одной командой нет намеренно: «прогнать скрипт и закоммитить»
обязано быть невозможным движением, иначе снимок перестаёт что-либо доказывать.

`tests/golden/known_bugs.json` — реестр известных дефектов: входы, на которых расчёт заведомо
врёт, записываются как есть, чтобы они не роняли сборку и при этом не потерялись. Тест
`test_golden.py` сверяет реестр с фактом, поэтому «случайно» появившийся баг в него не попадёт.
Сейчас реестр **пуст** (баг недоплаты в снежном коме — 262 кейса — исправлен), и он обязан
таким остаться: новая запись в нём означает новый принятый дефект, а не рабочую ситуацию.

## План развития

`ROADMAP.md` — один большой файл, читать его целиком не нужно. Полезные точки входа:

- **«Сводка хотелок»** (начало файла) — таблица W1–W9: что хочется, сколько это стоит,
  в какой итерации запланировано;
- **«Ключевые решения»** — 17 пронумерованных решений. Прежде чем менять поведение расчёта,
  стоит проверить, не описано ли оно там: решения 2 (инвариант досрочки), 4 (единая база
  начисления), 5 (метрика `own_cost`), 7 (паритет денежных потоков) и 17 (высвобожденный
  платёж дохода не приносит) — несущие;
- **«Итерации»** — план работ И0–И9 с приёмкой;
- **«Что осталось за скобками»** (конец файла) — что сознательно не делается.

`CHANGELOG.md` отвечает на вопрос «почему число стало другим»: у каждой записи, меняющей
числа, указаны замер «до → после» и конфигурация, в которой он снят.

## Инвариант, который нельзя ломать

**Досрочное погашение уходит на 100 % в тело долга и никогда не гасит проценты.**
Проценты, начисленные за уже прошедшую часть периода, предъявляются в полном объёме
на добытийный остаток. Строка досрочки в графике имеет `interest = 0`.

Это поведение по умолчанию (`principal_only`). Режим «сначала проценты, потом тело»
(`interest_first`) существует как явная настройка — некоторые банки проводят досрочку так.

## Что не поддерживается

Аутентификация и несколько пользователей, плавающая ставка, дифференцированные платежи,
страховки и комиссии, валюты кроме рубля.

Отдельно: **высвобожденный в режиме «уменьшить платёж» остаток не приносит дохода.** Вклады
начинаются от 50 000 ₽ и не пополняются, поэтому положить туда несколько тысяч в месяц некуда;
на вкладе лежит только разовая сумма. Эти деньги учитываются как непотраченные (иначе сравнение
стратегий было бы нечестным), но процентов на них не начисляется.

Запланировано и потому в этот список не входит: произвольное число досрочек (И9), НДФЛ по вкладу
опцией (И8), порог выгодности вклада (И8) — подробности в `ROADMAP.md`.
